# ИИ-пайплайн: как «Friendslop Motel» сделали ИИ-агенты

Этот документ объясняет, как сделан прототип. Человек ставил задачи и плейтестил, весь код, сцены, визуал и тесты написали ИИ-агенты: одна модель распределяла работу, другие писали код.

Документ для студентов. Он пригодится, если вы хотите повторить подход в своём проекте или разобрать, что в нём сработало, а что нет.

---

## 1. Кто что делал

| Роль | Кто | Что делает |
|---|---|---|
| **Заказчик / геймдизайнер** | человек | Даёт идею и правила, отвечает на вопросы, принимает решения, плейтестит в конце |
| **Оркестратор** | Claude Opus (в Claude Code) | Пишет диздок, правила для агентов и карточки задач; запускает агентов; проверяет их отчёты; общается с человеком. Сам код почти не пишет |
| **Агенты-исполнители** | Claude Sonnet (субагенты) | По одной карточке: пишут код на C#, собирают проект, гоняют автотесты, делают скриншоты, коммитят |

Агенты работали **по очереди, а не параллельно**. В Unity все трогают одну сцену и настройки проекта, и параллельная работа стоила бы дороже из-за конфликтов, чем сэкономила бы.

## 2. Этапы

```
Идея → Обсуждение и вопросы → Диздок + правила + карточки → Карточки по одной → Полировка → Плейтест → Правки → Сдача
```

1. **Обсуждение до кода.** Оркестратор предложил концепт, архитектуру и задал вопросы. К каждому вопросу был вариант по умолчанию, чтобы человек мог ответить одним словом. Код начали писать только после явного «да».
2. **Документы:**
   - [`GDD.md`](GDD.md) — правила игры и все числа;
   - [`AGENT.md`](AGENT.md) — правила для агентов: что читать, где писать код, как проверять, как коммитить;
   - [`CARDS.md`](CARDS.md) — список задач-карточек, строго по порядку.
3. **Ядро игры, C0–C6:** каркас и скрипты проверки → меню, сеть, игрок → локация и предметы в руках → номера, деньги, налоги → гости → кувалда и драки → финальная сборка.
4. **Полировка, P1–P4** ([`CARDS_POLISH.md`](CARDS_POLISH.md)): окружение и свет, персонажи и предметы, звук и интерфейс, шероховатости геймплея.
5. **Плейтест человеком** → багфиксы (например, «кувалда не бьёт»).
6. **Доработка v2, V1–V6** ([`CARDS_V2.md`](CARDS_V2.md)): день и ночь, растущий налог, магазин, туалет, табло задач в мире, грязные гости, неготовые номера.
7. **Сдача:** репозиторий на GitHub, билд, презентация для лекции.

## 3. Как устроена карточка

Карточка — короткое ТЗ на 20–40 минут работы агента. Пример из [`CARDS.md`](CARDS.md):

> **C4 — Гости.** NavMesh. Гость — сетевой префаб. Спавнер с интервалом из конфига. Заселение: очередь у стойки, ожидание 30 с, бланк → подпись 2 с → ключ готового номера → гость идёт в номер… **DoD:** полный цикл гость → деньги → обслуживание → новый гость.

У каждой карточки есть **DoD (Definition of Done)**, то есть проверяемое условие готовности. Агент не сдаёт карточку, пока оно не выполнено.

Агент заканчивает карточку так:
1. Один коммит `[C4] кратко`.
2. 2–4 строки в [`DECISIONS.md`](DECISIONS.md) в формате «решение — альтернатива — почему».
3. Отчёт оркестратору до 10 строк: что сделано, какие функции могут использовать следующие карточки, что проверить человеку.

Оркестратор передаёт этот список функций в промпт следующего агента. Получается эстафета знаний, и новому агенту не нужно перечитывать весь код.

## 4. Как ИИ проверял сам себя без человека

Это главная техническая часть. Без неё агенты не смогли бы работать автономно.

| Приём | Зачем |
|---|---|
| **Сцена собирается кодом** (`Builder.BuildAll()`), руками её никто не правит | Агент не может «кликать в редакторе», а код воспроизводим и не конфликтует |
| **Проверка без окна:** Unity в режиме batchmode компилирует проект и собирает сцену, скрипт ищет ошибки → `CHECK OK` | Каждая карточка проверяется автоматически |
| **Самотесты прямо в билде** через флаги (`-guesttest`, `-fighttest`, `-shoptest`…): два экземпляра игры, хост и клиент, сами проходят сценарий и пишут в лог `selftest OK/FAIL` | Проверяется не только компиляция, но и игровая логика по сети |
| **Скриншоты из билда** (`-shot`): игра сама ставит камеру, снимает PNG и выходит | Агент «видит» свой визуал и правит его итерациями |
| **Все числа баланса в одном `GameConfig`** | Баланс крутится без правки кода, легко найти и обсудить |

Всё это лежит в папке [`tools/`](../tools) и в скриптах `*SelfTest.cs`.

**Ограничение:** ощущения (управление, темп, звук, «весело ли») автотест не проверит. Это делал только человек на плейтесте.

## 5. Стоимость

Подсчёт по журналам сессии и по ценам API. По подписке реальная цена другая.

| Этап | Токенов | ≈ Цена по API | Время работы агентов |
|---|---:|---:|---:|
| Игра + полировка (C0–C6, P1–P4) | 98 млн | $37 | ≈ 3 ч |
| Доработка v2 (V1–V6) | 103 млн | $43 | ≈ 3 ч 10 мин |

- **97% токенов — чтение кэша.** Модель на каждом шаге перечитывает уже загруженный контекст, это самая дешёвая часть.
- **Полировка визуала стоила вдвое дороже самой игры:** десятки итераций «скриншот → правка».
- **Доработка оказалась дороже исходной игры:** чем больше кода, тем больше агенту читать.

## 6. Что сработало

- **Вопросы с вариантами по умолчанию** до начала работы: человек тратит минуты, а не часы.
- **Короткие карточки с DoD и автотестом на каждую механику.**
- **Журнал решений** ([`DECISIONS.md`](DECISIONS.md)): готовый материал для постмортема и лекции.
- **Эстафета функций** между агентами.
- **Дизайн-правило от человека** для магазина: «покупка не автоматизирует работу, а даёт инструмент». ИИ сам предлагал «робот моет пол», и это правило отсекло решения, которые ломали геймплей.

## 7. Что пошло не так (и чему учит)

| Проблема | Урок |
|---|---|
| Самотест проходил, а в игре «кувалда не била» | Тест вызывал серверную функцию напрямую, мимо ввода игрока. **Тест должен идти тем же путём, что и игрок** |
| Дальность удара 2,2 м была меньше дальности подсветки цели 2,5 м | Связанные числа держать рядом в конфиге и проверять вместе |
| Агент простоял 7 минут, потому что у человека был открыт редактор Unity | Автоматизация хрупка к «ручным» действиям; договориться о правилах заранее |
| ИИ пообещал отправить файл в Telegram, а инструмента для этого не было | Проверять возможности до обещания |
| Самые большие карточки (персонажи, табло задач в мире) стоили $8–9 | Резать задачи мельче, особенно визуальные |

## 8. Как повторить

1. Опишите идею и ответьте на вопросы ИИ-оркестратора.
2. Попросите его написать диздок, правила для агентов и карточки в стиле этого репозитория.
3. Первой карточкой сделайте каркас: проверку сборки без окна, самотесты, скриншоты из билда, конфиг чисел.
4. Дальше по одной карточке; на каждую механику — свой самотест.
5. Плейтестите сами: автотесты не скажут, весело ли играть.
6. Ведите журнал решений: он понадобится, когда придётся объяснять, почему игра именно такая.

Подробности для того, кто будет сам оркестратором, — в самих файлах: [`AGENT.md`](AGENT.md), [`CARDS*.md`](CARDS.md), [`DECISIONS.md`](DECISIONS.md), [`PRESENTATION.md`](PRESENTATION.md).
